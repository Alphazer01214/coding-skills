# STYLE — 中文技术文档写作规范

供 `doc-style` Phase 1–2 查阅。主对齐 [ruanyf/document-style-guide](https://github.com/ruanyf/document-style-guide)，并综合华为产品手册规范、W3C clreq、中文文案排版指北等（见文末）。

---

## §1 标题

**层级**：一级（文章标题）→ 二级（主要部分）→ 三级（小标题）→ 四级（某方面）。最多四级。

| 原则 | 错误 | 正确 |
|------|------|------|
| 一级下不得直接三级 | `# A` 后接 `### B` | 中间补 `##` |
| 避免孤立编号 | `## A` 下只有一个 `### A1` | 删掉 `### A1`，内容并入 `## A` |
| 下级不重复上级名 | `## 概述` / `### 概述` | `### 范围` 等具体名 |
| 慎用四级 | `### 下` 并列三个 `####` | 改 `**（1）**` 列表 |

## §2 文本

### 2.1 字间距

1. 中文与英文/半角字符之间**加一个半角空格**：`启动 Windows 系统`（非 `启动Windows系统`）
2. 中文与数字之间加不加空格均可，但**全文统一**。`6.5%` 视同数字
3. 数字与英文单位之间留空隙：`16 GB`、`1 h = 60 min`
4. 半角英文/数字与全角标点之间**不留空格**：`MacBook Air。`（非 `Air 。`）

### 2.2 句子

1. **句长**：≤20 字理想；20–29 可接受；30–39 须语义明确；**>40 不可接受**。逗号长句总长 ≤100 字或 3 行
2. **简单句/并列句**优先，避免复合句：「他昨天生病了，没有参加会议」优于「那个昨天生病的人没有参加会议」
3. **肯定句**优先：「请确认装置的电源已关闭」优于「请确认没有接通装置的电源」
4. **禁双重否定**：「用户必须拥有删除权限，才能删除此文件」优于「没有删除权限的用户，不能删除此文件」

### 2.3 写作风格

1. **主动语态**优先：「假如尚未安装这个软件」优于「假如此软件尚未被安装」
2. 正式书面语，不用口语/网络语/感叹体
3. 现代汉语常用表达，不用冷僻、生造、文言词：「仅有的两种」而非「唯二」
4. 的/地/得：形容词＋的＋名词；副词＋地＋动词；动词＋得＋副词
5. 代词（其/该/此/这）指代**唯一**：「中继系统和受中继系统直接控制的分配系统」而非「…受其直接控制…」
6. 名词前不堆形容词，长定语拆句后置

### 2.4 英文处理

1. 英文复数翻译回中文时还原单数：`(RAMs)` → `（RAM）`
2. 外文缩写用半角点：`U.S.A.`、`Apple, Inc.`
3. 中文语境省略号用 `⋯⋯`，不用 `...`
4. 英文书名/电影名译成中文后用书名号：`《航空业的未来》`
5. 英文词汇首次出现：`IOC（International Olympic Committee，国际奥林匹克委员会）`，此后直接用 `IOC`
6. 专有名词各词首字母大写；普通名词不大写

## §3 段落

- 一段**一个主题**，中心句放段首，后续句为中心句服务
- 长度 ≤7 行，最佳 ≤4 行
- 陈述/肯定语气，避免感叹
- 段间一个空行；段首不留空白字符
- 引用第三方须注明出处；全篇转载在开头注明作者并链至原文；外部图片在图下或文末标来源

## §4 数值

- 阿拉伯数字**一律半角**：`1000 元`（非 `１０００元`）
- 千位以上加千分号：`1,258,000`。四位数可省（`1000` 或 `1,000`）
- 货币：`$1,000` 或 `1,000 美元`；英文货币代码参考 ISO 4217
- 范围用 `～` 或 `—`：`132 kg～234 kg`、`67%～89%`（两端都带单位）
- 「增加了 N 倍」= 增量；「增加到 N 倍」= 定量。「降低了/降低到」同理
- **禁**「降低 N 倍」，改用「降低百分之几」

## §5 标点

### 5.1 总则

1. 中文语句用**全角**标点；整句英文用半角
2. 句号、问号、叹号、逗号、顿号、分号、冒号**不入行首**
3. 点号（。、，、；、：）**不入标题末尾**；标号（引号/括号/破折号/省略号/书名号/着重号/间隔号，以及叹号、问号）可以

### 5.2 分类

| 符号 | 规则 |
|------|------|
| 句号 `。` | 中文句尾用全角句号；句末括号加注时句号在括号**外**：`（见第 26 页）。` |
| 逗号 `，` | 一般停顿；避免「一逗到底」 |
| 顿号 `、` | 中文句内并列词用顿号（含英文词）：`Google、Facebook、腾讯`；英文句内并列用 `,`；末项尽量用「和」连接 |
| 分号 `；` | 复句内部并列分句之间 |
| 引号 | 中文用全角 `“ ”`；套引时外双内单 `‘ ’` |
| 括号 `（）` | 补充说明用全角圆括号，前后不加空格。名称对照：`{ }` 大括号 braces/curly brackets、`[ ]` 方括号 square brackets、`< >` 尖括号 angled brackets、`( )` 圆括号 parentheses |
| 冒号 `：` | 引出解释用全角；时间用半角 `8:00` |
| 省略号 `⋯⋯` | 占两字宽，含六个省略点；**禁** `。。。`、`...`；**不与「等」同用** |
| 感叹号 `！` | 尽量不用；禁连用 `！！` |
| 破折号 | 解释用；占两字宽，或 `——` 两侧留空格 |
| 连接号 `-` | 复合名词、图表编号：`氧化-还原`、`图 1-1` |
| 范围号 | 数值范围用 `～` 或 `—`：`2009 年～2011 年`；也可用「至」 |

## §6 降 AI 味硬指标

写作/改稿时优先扫这些（与 §2–§5 对应，是 AI 最常犯的）：

| AI 味信号 | 规范动作 | 出处 |
|-----------|----------|------|
| 40+ 字长句、复合句套叠 | 拆成简单句/并列句 | §2.2 |
| 被动语态（被/受到/由…进行） | 改主动 | §2.3 |
| 双重否定、绕圈否定 | 改肯定句 | §2.2 |
| 名词前一串形容词 | 拆句或后置 | §2.3 |
| 「其/该/此」指代不清 | 点名所指 | §2.3 |
| 中英文粘连无空格 | 补半角空格 | §2.1 |
| 半角标点混入中文句 | 改全角 | §5.1 |
| `...`、`！！`、`。。。` | 改 `⋯⋯`、删感叹号 | §5.2 |
| 一逗到底 | 拆句、改用句号/分号 | §5.2 |
| 段落无中心句、超 7 行 | 段首立中心句、拆段 | §3 |
| 标题跳级/孤立编号 | 补层级或删孤立 | §1 |
| 全角数字 `１０００` | 改半角 | §4 |

## §7 文档体系

### 7.1 手册骨架

- **简介**（Introduction）[必备][文件] 总体扼要说明
- **快速上手**（Getting Started）[可选][文件] 最快用起来
- **入门篇**（Basics）[必备][目录] 环境准备（Prerequisite）[必备][文件] · 安装（Installation）[可选][文件] · 设置（Configuration）[必备][文件]
- **进阶篇**（Advanced）[可选][目录] 中高级教程
- **API**（Reference）[可选][目录|文件] 逐一介绍
- **FAQ** [可选][文件]
- **附录**（Appendix）[可选][目录] Glossary · Recipes · Troubleshooting · ChangeLog · Feedback（各 [可选][文件]）

范例：[Redux 手册](https://redux.js.org/introduction/getting-started)、[Atom 手册](http://flight-manual.atom.io/)

### 7.2 文件名

- 不得含空格；只用半角（中文不能作文件名）：`glossary.md`（非 `名词解释.md`）
- 建议全小写：`troubleshooting.md`（非 `TroubleShooting.md`）；`README`、`LICENSE` 除外
- 多词用 `-` 分隔：`advanced-usage.md`（优于 `advanced_usage.md`）
