# Doc Style

中文技术文档的写作门禁。**规范落地 = 降 AI 味**：AI 常见病（长句套叠、被动语态、中英粘连、标点混用、段落无主）正是本规范要治的。

**何时**：写/改中文技术文档。纯英文文档、代码注释、对话体不在范围。

**互补**：句式/腔调层的 AI 痕迹（翻案腔、破折号滥用、拟人喻体等）→ 成稿后跑 `lieflat-less-ai-tone`。本 skill 管**规范层**（结构、间距、标点、句长、语态）。

## Phase 0 — Intake

确认：文档类型（手册/设计/报告/README）· 受众 · 新写还是改稿 · 目标路径。

**完成**：类型 + 受众 + 路径明确。改稿需先通读全文。

## Phase 1 — Structure

标题层级与文档体系，详 [STYLE.md](STYLE.md) §1 §7。

- 标题 ≤4 级；一级下不得直接三级；避免孤立编号；下级不重复上级名
- 软件手册骨架：简介 → 快速上手 → 入门 → 进阶 → API → FAQ → 附录
- 文件名：小写、半角、`-` 分隔、无空格

**完成**：标题树合法；改稿时列出结构违规点。  
**门禁**：跳级或孤立编号未处理 → 不进入正文改写。

## Phase 2 — Write / Revise

按 [STYLE.md](STYLE.md) §2–§6 逐项写或改：

1. **文本**：中英/中数间距；句长 ≤20 字（40 字封顶）；简单句、主动句、肯定句；的/地/得；代词指代唯一
2. **段落**：一段一主题；中心句在段首；≤7 行（最佳 ≤4）；陈述语气
3. **数值**：半角数字；千分位；范围用 `～`；「增加了/增加到」区分
4. **标点**：中文句全角；点号不入行首；标题末无点号；慎用感叹号

改稿纪律：只改违反规范处，不增删信息、不重组论证。

**完成**：正文过完一遍规范，违规清零或已标注。  
**门禁**：为改句式而新增/删减事实 → 撤销该改动。

## Phase 3 — De-AI 扫

规范里直接压 AI 味的硬指标，再扫一遍（详 [CHECKLIST.md](CHECKLIST.md) §A）：

长句套叠 · 被动语态 · 双重否定 · 形容词堆砌 · 代词悬空 · 中英粘连 · 半角标点入中文句 · 感叹号连用 · 一逗到底 · 段落无中心句

**完成**：上述信号清零。

## Phase 4 — Verify

跑 [CHECKLIST.md](CHECKLIST.md)。摘要：改了什么 / 没改什么 / 残留风险。

**完成**：清单全过，用户确认摘要。

## 边界

只规范文档语言与结构，不改技术内容、代码块、外语段落、引用原文。拿不准是否违规时保留原文并标注。
